## Critical

### C-1 — Bundled extension registry is empty on any real install

`gvm/extensions.py:33`, `pyproject.toml`

```python
EXTENSIONS_REPO = Path(__file__).parent.parent / "extensions-repo"
```

`extensions-repo/` sits at repo root. `packages.find` includes only `["gvm*"]`, `package-data` lists only `py.typed`, and there is no `MANIFEST.in`.

Built the wheel and listed it — 19 files, no TOMLs:

```
gvm/__init__.py  gvm/__main__.py  gvm/cache.py  gvm/extensions.py
gvm/ghidra_props_parser.py  gvm/gui.py  gvm/install.py  gvm/main.py
gvm/py.typed  gvm/prefs_backup/*.py  + dist-info
```

Runtime confirmation from a clean venv:

```
EXTENSIONS_REPO    = .../site-packages/extensions-repo
bundled dir exists = False
registry entries   = 0
```

And the user-facing symptom:

```
$ gvm extensions list
INFO Known extensions:
$
```

An empty heading, no error. `Path.glob` on a missing directory yields nothing, so the failure is completely silent. Only editable installs work, which is why it's gone unnoticed — and CI runs `pip install .` but never calls `extensions list`, so CI misses it too.

**Fix:** move `extensions-repo/` to `gvm/extensions-repo/`, add to `package-data`, resolve via `importlib.resources.files("gvm")`. **~45 min.**
**Verification:** `gvm extensions list` in a clean venv prints 27 entries.

### C-2 — macOS install crashes mid-install on any pip install

`gvm/install.py:336-338`

```python
plist_template = (
    Path(__file__).parent.parent / "res" / "macos_plist.plist"
).read_text(encoding="utf-8")
```

Same packaging gap — `res/` is not in the wheel. Confirmed:

```
macos plist path   = .../site-packages/res/macos_plist.plist
macos plist exists = False
```

There is no `try`/`except` around this read. On macOS it raises `FileNotFoundError` **after** the release zip has been downloaded and extracted, **after** `/Applications/Ghidra_X.app` has been created, and **before** `apply_ui_scale` and `cacher.save()`. Result: a fully extracted Ghidra that GVM has no record of, plus an empty broken `.app` bundle in `/Applications`, plus a traceback.

macOS installs are 100% broken for every non-editable install. This is invisible to you because you develop on Windows and CI is Ubuntu-only.

**Fix:** ship `res/` as package data alongside C-1, and wrap the launcher block so a cosmetic failure can't orphan an otherwise-good install. **~30 min** (shares the packaging work with C-1).

### C-3 — Arbitrary file write and command injection via release metadata

`gvm/install.py:261, 280, 291`

Three weaknesses compose:

```python
version   = file_name.split("_")[2]                      # from release['tag_name']
exec_cmd  = f"{us} -m gvm --launcher run {tag}"          # NOT quoted
desktop   = app_dir / f"ghidra_{version}.desktop"        # version interpolated into a path
```

The `len(parts) >= 3` guard added in `ISSUES.md` #2 checks the *count* of segments, not their *content*. A tag of the form `a_<payload>_b` puts `<payload>` straight into `version`:

```
tag='a_../../../../../../tmp/evil_b'
    version  = '../../../../../../tmp/evil'
    .desktop resolves to -> /sessions/tmp/evil.desktop
```

The `.desktop` file escapes `~/.local/share/applications` entirely — it can be written anywhere the user can write, including `~/.config/autostart/`.

Separately, `ISSUES.md` #14 applied `shlex.quote` to the macOS launcher and left the Linux one raw:

```
Linux  Exec= /usr/bin/python3 -m gvm --launcher run Ghidra_11.4_build; touch /tmp/pwned
macOS  exec  /usr/bin/python3 -m gvm --launcher run 'Ghidra_11.4_build; touch /tmp/pwned'
```

Under your chosen threat model the release JSON is attacker-controlled (MITM, or a compromised upstream), so both halves are reachable: write an autostart entry whose `Exec=` line runs an injected command.

**Fix:** validate `version` against `^[A-Za-z0-9.\-]+$` and reject anything else; `shlex.quote` the Linux `Exec=` (and prefer `Exec=` with an argv array over string interpolation); derive `version` from a parsed release field rather than string-splitting a filename. **~1.5 hrs.**

## High

### H-1 — `--offline` does not prevent network access

`gvm/main.py:280-284`

`main()` runs the implicit update check with no reference to `args.offline`:

```python
if _allow_update_check(cmd):
    ...
    do_update_check(cacher, args)
```

Instrumented `requests.get` and ran `gvm --offline install Ghidra_11.4_build` against a fresh cache:

```
NETWORK CALLS MADE WITH --offline: 1
   -> https://api.github.com/repos/NationalSecurityAgency/ghidra/releases/latest
```

The flag's entire purpose is defeated. On an air-gapped or metered machine every command pays a 30-second timeout before doing anything.

**Fix:** add `and not getattr(args, "offline", False)` to the gate. **~10 min.** Better: thread an `offline` flag through a small network wrapper so no future call site can forget.

### H-2 — An unavailable `install_dir` bricks every command

`gvm/main.py:256, 263`

```python
default_path.mkdir(parents=True, exist_ok=True)
...
path = Path(cacher.cache.prefs.install_dir)
path.mkdir(parents=True, exist_ok=True)
```

Neither is guarded. Set `install_dir` to an external drive, unplug it, and every command dies:

```
$ gvm --offline prefs show
PermissionError: [Errno 13] Permission denied: '/mnt/big'
```

Including `gvm prefs set install_dir default` — the one command that would fix it. The user's only recovery is hand-editing `cache.toml`.

The irony: `main.py:380-389` handles exactly this scenario gracefully for the *run* path, with a comment about unmounted locations. That care just isn't applied at startup.

**Fix:** wrap both `mkdir` calls, report a clear message naming the pref and how to reset it, and let read-only commands (`prefs`, `locate`, `list`) proceed without the directory. **~45 min.**

### H-3 — Non-atomic cache write plus reset-on-any-error equals silent state loss

`gvm/cache.py:240-245` and `220-238`

```python
def save(self) -> None:
    data = self.cache.to_dict()
    with open(self.cache_path, "wb") as f:   # truncates immediately
        tomli_w.dump(data, f)
```

No temp-file-and-rename. A crash, power loss, or full disk mid-write leaves a truncated `cache.toml`.

`load()` then catches bare `Exception` and starts fresh. Reproduced with a truncated file:

```
ERROR Failed to load old cache: Expected '=' after a key in a key/value pair
INFO Use PyGhidra in launchers? {py3} [no]              <- was true
INFO Override ui scale {scale} [1]                      <- was 2
INFO Install directory {install_dir} [...] (default)    <- was /mnt/big/ghidra
```

One ERROR line, then GVM carries on as a fresh install. Every installed version, every installed extension, the default version and all prefs are gone from GVM's view. The next command that calls `save()` overwrites the damaged file with empty state, destroying any chance of manual recovery.

**Fix:** write to `cache.toml.tmp` then `os.replace()`; on load failure, rename the bad file to `cache.toml.corrupt-<timestamp>` and tell the user where it went rather than silently discarding it. **~1 hr.** This also underpins the GUI/CLI locking work in R-3.

### H-4 — Prefs migration has no rollback *(static)*

`gvm/main.py:144-171`, `prefs_backup/backup_restorer.py:27-50`

You specified: on failure, roll back and launch. Current behavior does not do that.

- `install_fn()` is called unguarded.
- `restorer.restore_to_cached_version(...)` is called unguarded — if it throws, the new version's prefs are half-written.
- `restore_to_cached_version` does `pref_path.write_bytes(prefs_data)` with **no pre-image of the file it is overwriting**, so there is nothing to roll back *to*.
- That write is itself non-atomic, so an interruption corrupts the user's Ghidra preferences.

**Fix:** snapshot the destination prefs before writing, write via temp+rename, and on any exception restore the snapshot and log clearly. **~2 hrs.**

### H-5 — Integrity verification silently skipped when no digest is published

`gvm/install.py:42-46`

```python
digest = asset.get("digest") or ""
if not digest.startswith("sha256:"):
    logger.debug("No sha256 digest published ...; skipping integrity check")
    return
```

`ISSUES.md` #5 documents this as acceptable best-effort. Under the threat model you selected it is not: a network attacker who can alter the download can also strip the `digest` field from the API response, downgrading verification to nothing — and the notice is at `debug` level, so the user never sees it.

**Fix:** promote the skip to a visible warning; add `--require-digest` (and consider defaulting it on) so integrity can be enforced; verify TLS-pinned host and reject `browser_download_url` values that aren't on a GitHub host. **~1.5 hrs.**

## Medium

**M-1 — `_GH_NAME_RE` accepts `..` and `.`** (`extensions.py:42`). The regex is `^[A-Za-z0-9._-]+$`; `.` is in the class, so `..` matches. Tested: `'..' -> match=True`. The comment above it claims "this stops path separators ('..', '\\')" — the code does not do what it says. `https://github.com/../../etc/repo` parses to `('..','..')` and produces the API URL `.../repos/../../releases/latest`. Not a host escape, but a validation bypass that shouldn't exist. **~15 min:** reject `.`/`..` explicitly and require a leading alphanumeric.

**M-2 — `parse_git_url` silently discards the hostname** (`extensions.py:122`). Tested: `https://evil.com/owner/repo -> ('owner','repo')`. The user believes they added an extension from evil.com; GVM fetches from github.com instead. Since you're keeping arbitrary-URL add, this silent substitution is the wrong failure mode in both directions. **~30 min:** reject non-GitHub hosts explicitly rather than ignoring them.

**M-3 — Cached-zip reuse is on by default** (`install.py:204`). `if dl_path.exists() and __debug__:` — `__debug__` is True in every normal run; it's False only under `python -O`. The comment calls this a development convenience, but it is the default path for all users. The filename is predictable and lives in a directory that may be shared. Digest verification does run afterward, which mitigates it — but only when a digest is published (see H-5). **~20 min:** gate on an explicit env var or `--use-cached` flag.

**M-4 — Unguarded asset download** *(static)* (`install.py:211-212`). The metadata fetch is wrapped in `try/except requests.RequestException`; the actual asset download two lines later is not. A dropped connection surfaces as a raw traceback. **~15 min.**

**M-5 — Blind `assets[0]`** *(static)* (`install.py:194`). `extensions.py` has `_select_asset` with `asset_pattern` glob support, added precisely because "multi-asset releases fetch the intended file instead of a blind first asset." `install.py` still does the blind thing. If a Ghidra release ever adds a signature or checksum asset first, installs break. **~30 min:** reuse `_select_asset`.

**M-6 — Emoji in log output** *(static)* (`install.py:198,202,238,253,351`; `main.py:89`). `⬇️ 💾 📦 ⚙️ 📜 🔔`. On a Windows console still using a legacy code page these raise `UnicodeEncodeError` inside the logging handler. You want Windows first-class; this is untested there. **~20 min:** ASCII fallback, or force UTF-8 on the stream handler.

**M-7 — `apply_ui_scale` assumes paths exist** *(static)* (`install.py:272-275, 382-383`). If neither `ghidra_<v>_PUBLIC` nor `ghidra_<v>` exists after extraction, `dir_path` points at nothing and every downstream operation fails obscurely; `shutil.copy2(props_path, ...)` then raises an unguarded `FileNotFoundError`. **~30 min:** assert the extracted directory exists with a clear message before proceeding.

## Low

- **L-1** `_generate_slug` (`extensions.py:668`): names of only punctuation collapse to `local-`, so `"!!!"` and `"   "` both write `local-.toml` and silently overwrite each other. **~15 min.**
- **L-2** `subprocess.Popen([str(runner)], shell=True)` (`main.py:403`): correct on Windows — `list2cmdline` quotes properly and `.bat` genuinely needs a shell — but `shell=True` with a list is a pattern that breaks badly if this code is ever reused on POSIX. Prefer `["cmd", "/c", str(runner)]`. **~10 min.**
- **L-3** `dl_path.unlink()` (`install.py:364`) without `missing_ok=True`. **~5 min.**

## Architecture

**gui.py is 1,978 lines — 46% of the codebase.** The threading model is genuinely well built: `_run_threaded` on daemon threads, one heavy task at a time, results marshalled back with `after(0, …)` and guarded by `winfo_exists()`. I went looking for cross-thread widget access and did not find it. That's the hard part, and it's right.

The problem is that all three tabs, the launcher, the single-instance lock, and the settings persistence live in one module, and much of the CLI's logic is reimplemented there rather than shared.

**Suggested split**, ordered so the GUI runs after every step:

1. `gui/widgets.py` — `_lock_scroll`, row builders, small helpers. Pure extraction, no behavior change. *(~1 hr)*
2. `gui/tasks.py` — `_run_threaded`, `_thread_wrapper`, `_poll_queue`, status var. *(~1.5 hrs)*
3. `gui/lock.py` — single-instance lock and `_pid_is_running`. Natural home for the CLI-blocking lock in R-3. *(~1 hr)*
4. `gui/tabs/versions.py`, `extensions.py`, `settings.py` — one tab at a time. *(~2 hrs each)*
5. `gui/app.py` — the shell that wires them together. *(~1 hr)*

**Shared core:** rather than have the tabs call `main.py` (which is argparse-shaped), extract a `gvm/service.py` of plain functions — `install(tag)`, `uninstall(tag)`, `run(tag)`, `set_pref(k, v)` — that both `main.py` and the GUI call. That's what makes the CLI/GUI divergence go away permanently, and it's what makes the code testable. **~4 hrs**, best done after step 2.

**Other maintainability items:**

- **Zero tests.** For a package others install, the highest-value eight are: wheel-contains-registry, `_safe_extract_zip` (the three cases I ran), `parse_git_url` hostile inputs, `Cache` round-trip and corrupt-file recovery, `_resolve_tag` empty-tag paths, `--offline` makes no network calls, `_generate_slug` collisions, prefs backup/restore round-trip. **~6 hrs** for all eight plus fixtures.
- **CI gaps.** Ubuntu only, 3.11/3.12 only, no test run, no lint, no type check, and no command that would have caught C-1 or C-2. Add a Windows and macOS matrix leg and a clean-venv smoke test that asserts 27 extensions. **~2 hrs.**
- **`py.typed` is shipped**, which advertises type completeness to downstream users. No type checker runs in CI, so that promise is unverified.
- **`.claude/worktrees/gallant-galileo-679816/`** — a full stale copy of the repo committed inside the repo, with a divergent `gvm/` and no `gui.py`. Delete it. **~5 min.**
- **Tracked `__pycache__` for CPython 3.14**, outside both the declared floor and the CI matrix. Add to `.gitignore` and `git rm -r --cached`. **~10 min.**
- **Unpinned dependency floors** with no upper bounds. For public distribution, consider upper bounds on `requests` and `pillow`.
- **Unauthenticated GitHub API.** 60 requests/hour anonymous. Honour `GITHUB_TOKEN` when present. **~30 min.**
